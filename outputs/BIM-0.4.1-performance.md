# BIMViewer 0.4.1 性能诊断与优化路线

## 已实现

底部工具栏新增“性能监控”。打开后旋转、平移模型即可观察交互表现；勾选“持续渲染”可在固定视角采样。支持重置和下载 JSON 报告。关闭面板即停止强制持续渲染，默认仍按需绘制。

包含 FPS、平均/P95 帧间隔、慢帧、CPU 渲染提交、拾取、材质更新、加载准备时间；Draw Calls、三角形、构件/网格数、真实实例化批次/实例数、LOD 组和层级；几何/材质/纹理/Shader 数量、缓冲分辨率及内存估算。统计每秒更新两次，保留最近最多 120 个有效帧间隔。

## 优化顺序

补充复测：同分辨率固定视角导出的 `bim-041-performance-report.json` 记录约 12.4 FPS、80.7 ms 平均帧间隔、86.3 ms P95、79.4 ms CPU 提交。两次采样的绘制调用和三角形数一致。两次之间没有实施渲染优化，因此不能将差值解释为优化收益。

1. **先降低绘制提交成本。** 复用材质；按材质及空间分块合批，避免把全楼合成无法剔除的一个巨型网格。保留三角形/实例与稳定构件 ID 的映射，回归验证拾取、属性、隐藏、隔离和剖切。选中态优先用独立覆盖层或专用状态，避免逐构件克隆材质。
2. **重复几何实例化。** 仅对真正相同的几何与材质做实例化；同族构件仍可能因开洞、参数和裁切不同而不能共享，不能简单按族名合并。
3. **减面与 LOD。** 优先控制圆管、弯头等曲面离散精度，离线生成多级几何，以屏幕误差或投影尺寸切换。远景简化、近景保留精度，属性与 ID 不变。当前版本只监控 LOD，并未实现 LOD 加速。
4. **更大模型采用分块加载。** 楼层、系统结合空间块，视锥剔除、按需加载/卸载及缓存预算；逐步加入后台解析和取消请求。单个巨型 GLB 全量加载不适合作为长期架构。
5. **按测量结果优化拾取。** 当拾取明显成为瓶颈，再加空间候选过滤/BVH；本次约 9 ms 的拾取低于渲染帧成本，因此不是第一优先级。

Draco/meshopt 压缩主要针对传输与存储，不能替代合批、减面和 LOD。下一轮应在相同模型、分辨率、相机及显示设置下做改前/改后比较，同时验证构件操作正确性。

## 统计边界

- 静止按需渲染显示“-- FPS”，不是卡到 0 FPS；空闲间隔不计入帧间隔。持续采样模式切换会清空历史。
- CPU 渲染提交不是 GPU 执行时间，本版 GPU 时间显示未采集，不能据此断言只有 CPU 瓶颈。
- 提交三角形包含透明材质额外绘制，不代表屏幕可见面数。“显示开启”不代表通过视锥或遮挡测试。
- 实例数指真实 InstancedMesh 实例，不是构件数量。当前包实例化、LOD 均为零。
- 几何数组和浏览器 JS 堆仅为估算，不是显存。加载准备不含之前的文件/包读取及首次 GPU 上传。
- 报告仅在本地下载，含视角、显示设置和统计，不含模型文件内容。

## 验证与范围

30 项自动测试通过，前端生产构建通过，保留既有的大文件块警告。浏览器验证了小模型、大模型、持续采样和实际拾取。新增测试覆盖空闲采样、慢帧、历史上限、共享几何、实例化及 LOD 计数。

本轮交付诊断工具，不宣称已经完成大模型性能优化。Revit 插件仍为 0.3.0，无 DLL 更新，也不需要重启 Revit。
