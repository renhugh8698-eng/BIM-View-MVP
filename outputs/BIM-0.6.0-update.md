# BIMViewer 0.6.0：分批处理与保守实例化

## 两份报告的结论

| 指标 | 边线关闭 | 边线开启 |
| --- | ---: | ---: |
| FPS | 37.05 | 22.91 |
| 平均帧间隔 | 26.99 ms | 43.65 ms |
| Draw Calls | 1,797 | 3,470 |
| 提交三角形 | 12,005,557 | 12,005,557 |
| 提交线段 | 0 | 5,700,913 |
| 合批缓存 | 416.0 MiB | 583.2 MiB |

开启边线后空间合批仍在生效，并非退回逐构件绘制。新增线段和绘制调用增加了每帧负担；首次边线更新约 22.47 秒，是另一个需要解决的交互阻塞问题。两份报告的相机位置略有不同，因此不能视为严格同视角基准。

## 本轮完成的范围

1. 优化任务与边线任务分开计时，报告包含任务状态、总历时、CPU 工作时间、最长连续分片和让出主线程次数。
2. 空间合批和边线生成改为可取消的分批任务。模型先以原始方式显示，合批完成后切换；边线逐批出现。切换模型、优化选项会取消旧任务，避免旧结果覆盖新模型。
3. 推进重复几何实例化：严格比较平移归一化后的顶点、法线、UV 等属性及索引，同时限制材质、类别和空间分区。至少三个匹配才考虑实例化；若拆组会增加预计表面 Draw Calls，则继续空间合批。保留原始构件 ID、精确拾取及选中/隐藏/隔离路径。

设置中新增“重复几何实例化”，默认开启，可随时关闭进行对照。任务提示旁的关闭图标可取消当前优化；再次切换相关设置可重新开始。

没有推进 LOD、减面、分块流式加载，也没有修改 Revit 导出器。DLL 不变，无需重新加载插件。

验证情况：43 项自动化测试通过（包含现有真实数据包与 C# 导出样本），TypeScript 检查与生产构建通过；仍有原有的包体大于 500 kB 提示。按本轮分工，没有执行浏览器操作与性能对照测试。

## 请回传三组数据

刷新页面并重新加载同一个模型，保持空间合批开启、原始材质模式、相同视角和窗口尺寸，不选中/隐藏/隔离构件：

1. 实例化关闭，边线关闭。
2. 实例化开启，边线关闭。
3. 实例化开启，边线开启。

每组都先等待优化/边线任务显示完成，再在性能监控中开启持续渲染，重置采样，等待约 10 秒后下载 JSON。全过程不移动相机；只切换设置即可。三份报告直接发回即可，不必截图抄数字。测完关闭持续渲染，恢复静止时停止绘制。

若实例命中为零，也请回传原始报告。这可能是烘焙几何不完全相同、材质/空间分组不同，或新增绘制调用保护生效，不代表报告失效。

## 边界与下一步

- 分批处理减少持续阻塞，不保证缩短总处理时间或提高稳定 FPS。8 ms 是目标预算，单个大构件的边线计算、几何合并和首次 GPU 上传仍可能超过它。
- 本轮的实例化主要减少重复表面缓存，不减少全精度三角形；边线复用提取结果，但仍存储各构件的线段数组。
- 原始拾取几何仍保留。报告中的“减少表面数组复制”不是浏览器总内存或显存下降量。
- 等三组结果回来后，再决定优先把大构件边线处理移入 Worker，还是优化远距离边线显示及推进 LOD；本轮不提前实施。
